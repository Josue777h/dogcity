# Base de Datos y Servicios de Supabase en Camly

Este documento contiene el modelo de datos formal, políticas RLS, triggers, almacenamiento multimedia y servicios de backend implementados con Supabase.

---

## 1. Esquema de Base de Datos Relacional (PostgreSQL)

El sistema opera bajo 6 tablas fundamentales definidas en `camly-app/supabase/schema.sql`:

### 1.1. Tabla `negocios` (Perfil del Comercio)
Contiene la configuración de cada tenant registrado:
* `id` (`UUID`, PK, `DEFAULT gen_random_uuid()`): Identificador interno del negocio.
* `user_id` (`UUID`, FK hacia `auth.users.id`): Usuario propietario en Supabase Auth.
* `nombre` (`TEXT NOT NULL UNIQUE`): Slug de la URL pública (ejemplo: `pizzaliberty`).
* `nombre_visible` (`TEXT NOT NULL`): Nombre comercial visible (ejemplo: *"Pizzería Liberty Gourmet"*).
* `telefono` (`TEXT`) y `whatsapp_contacto` (`TEXT`): Números para llamadas y recepción de pedidos formateados internacionalmente.
* `direccion` (`TEXT`): Dirección física del local.
* `lat` y `lng` (`NUMERIC`): Coordenadas GPS del punto de despacho. Vital para el cálculo de distancias.
* `tipo_domicilio` (`TEXT DEFAULT 'automatico'`): Modo de tarifa (`'automatico'` por km, `'fijo'`, o `'gratis'`).
* `costo_por_km` (`NUMERIC DEFAULT 0`): Tarifa en moneda local por cada kilómetro recorrido.
* `domicilio_minimo` (`NUMERIC DEFAULT 0`): Tarifa piso o mínima de entrega.
* `precio_domicilio` (`NUMERIC DEFAULT 0`): Tarifa estándar fija cuando no se usa cálculo por km.
* `theme_color` (`TEXT DEFAULT '#EA580C'`): Color primario para botones y acentos de marca.
* `color_secundario` (`TEXT DEFAULT '#FFF7ED'`): Color de fondo o contraste secundario.
* `metodos_pago` (`JSONB DEFAULT '["efectivo","transferencia"]'::jsonb`): Métodos activos.
* `pago_banco` y `pago_alias`: Información bancaria para transferencias (Nequi, Daviplata, Bancolombia).
* `instagram`, `facebook`, `tiktok`, `footer_message`, `logo_url`: Redes e identidad visual.
* `created_at`, `updated_at` (`TIMESTAMPTZ`).

### 1.2. Tabla `categorias` (Clasificación de Productos)
* `id` (`BIGINT GENERATED BY DEFAULT AS IDENTITY`, PK).
* `negocio_id` (`UUID NOT NULL`, FK hacia `negocios(id)` ON DELETE CASCADE).
* `nombre` (`TEXT NOT NULL`).
* `created_at` (`TIMESTAMPTZ`).
* **Restricción:** `UNIQUE (negocio_id, nombre)`.

### 1.3. Tabla `productos` (Catálogo / Menú)
* `id` (`BIGINT GENERATED BY DEFAULT AS IDENTITY`, PK).
* `negocio_id` (`UUID NOT NULL`, FK hacia `negocios(id)` ON DELETE CASCADE).
* `categoria_id` (`BIGINT`, FK hacia `categorias(id)` ON DELETE SET NULL).
* `nombre` (`TEXT NOT NULL`).
* `precio` (`NUMERIC NOT NULL DEFAULT 0`).
* `descripcion` (`TEXT DEFAULT ''`).
* `unidad` (`TEXT DEFAULT 'unidad'`).
* `imagen` (`TEXT DEFAULT ''`): URL de la imagen en Supabase Storage.
* `categoria` (`TEXT DEFAULT ''`): Nombre de categoría redundante para búsquedas rápidas.
* `disponible` (`BOOLEAN DEFAULT true`): Control de stock y visibilidad inmediata.
* `created_at`, `updated_at` (`TIMESTAMPTZ`).

### 1.4. Tabla `domiciliarios` (Equipo de Repartidores)
* `id` (`UUID`, PK, `DEFAULT gen_random_uuid()`).
* `negocio_id` (`UUID NOT NULL`, FK hacia `negocios(id)` ON DELETE CASCADE).
* `nombre` (`TEXT NOT NULL`).
* `telefono` (`TEXT NOT NULL`).
* `activo` (`BOOLEAN NOT NULL DEFAULT true`).
* `created_at` (`TIMESTAMPTZ`).

### 1.5. Tabla `suscripciones` (Control SaaS & Monetización)
* `id` (`UUID`, PK, `DEFAULT gen_random_uuid()`).
* `negocio_id` (`UUID NOT NULL`, FK hacia `negocios(id)` ON DELETE CASCADE, UNIQUE).
* `plan` (`TEXT NOT NULL DEFAULT 'pro'`): Nivel de suscripción (`'free'`, `'pro'`, `'enterprise'`).
* `estado` (`TEXT NOT NULL DEFAULT 'trial'`): `'trial'`, `'activo'`, `'vencido'`, `'cancelado'`.
* `es_trial` (`BOOLEAN NOT NULL DEFAULT true`).
* `fecha_inicio` (`TIMESTAMPTZ DEFAULT NOW()`).
* `fecha_fin` (`TIMESTAMPTZ`): Fecha límite tras la cual se activa el paywall `PlanExpiredView`.
* `created_at`, `updated_at` (`TIMESTAMPTZ`).

### 1.6. Tabla `pedidos` (Órdenes y Transacciones)
* `id` (`BIGINT GENERATED BY DEFAULT AS IDENTITY`, PK).
* `negocio_id` (`UUID NOT NULL`, FK hacia `negocios(id)` ON DELETE CASCADE).
* `domiciliario_id` (`UUID`, FK hacia `domiciliarios(id)` ON DELETE SET NULL).
* `nombre` (`TEXT NOT NULL`): Nombre del cliente comprador.
* `telefono` (`TEXT NOT NULL`): Teléfono de contacto del cliente.
* `direccion` (`TEXT`): Dirección escrita o barrio.
* `ubicacion_link` (`TEXT`): Enlace directo de Google Maps generado con las coordenadas del cliente.
* `comentarios` (`TEXT DEFAULT ''`): Instrucciones para cocina o entrega.
* `total` (`NUMERIC NOT NULL DEFAULT 0`): Monto total de los productos.
* `domicilio_costo` (`NUMERIC DEFAULT 0`): Costo calculado de flete.
* `distancia_km` (`NUMERIC`): Distancia calculada entre negocio y cliente.
* `items` y `productos` (`JSONB DEFAULT '[]'::jsonb`): Array con el desglose de productos, cantidades, precios unitarios y notas.
* `estado` y `status` (`TEXT DEFAULT 'nuevo'`): `'nuevo'`, `'preparando'`, `'en camino'`, `'entregado'`, `'cancelado'`.
* `entrega_metodo` (`TEXT DEFAULT 'envio'`): `'envio'` o `'recoger'`.
* `pago_metodo` (`TEXT DEFAULT 'efectivo'`): `'efectivo'`, `'transferencia'`, etc.
* `token` (`TEXT`): Token único para acceso público de rastreo en `/tracking?t=:token`.
* `created_at`, `updated_at` (`TIMESTAMPTZ`).

## 2. Automatizaciones y Triggers en Base de Datos

### Trigger `trg_sync_pedido_status`
En `schema.sql` existe la función `fn_sync_pedido_status()` ejecutada `BEFORE INSERT OR UPDATE ON pedidos`:
1. Sincroniza bidireccionalmente las columnas `estado` y `status` si una de las dos es modificada por código legado.
2. Sincroniza bidireccionalmente los campos JSONB `items` y `productos` para evitar discrepancias entre versiones del checkout.

## 3. Políticas de Seguridad (RLS - Row Level Security)

### Estado Actual en Desarrollo:
Actualmente todas las tablas tienen RLS habilitado, pero con políticas permisivas:
```sql
CREATE POLICY "Public access on negocios" ON negocios FOR ALL USING (true) WITH CHECK (true);
-- Repetido para categorias, productos, domiciliarios, suscripciones y pedidos
```
> [!WARNING]
> **Hallazgo Crítico de Seguridad:**
> Aunque permite un desarrollo ágil sin bloqueos, en un entorno de producción real esto permite que cualquier cliente autenticado o anónimo pueda potencialmente ejecutar mutaciones sobre pedidos o catálogos ajenos si interactúa directamente con la API pública de Supabase.

### Plan de Securización para Producción:
* **Lectura Pública:**
  * `negocios`: SELECT público permitido (para cargar la tienda por slug).
  * `categorias`: SELECT público permitido filtrado por `negocio_id`.
  * `productos`: SELECT público permitido (`disponible = true`).
  * `pedidos`: SELECT restringido por `token` (para la vista `/tracking`).
* **Operaciones de Gestión (Admin):**
  * INSERT/UPDATE/DELETE en `categorias`, `productos`, `domiciliarios`, `suscripciones` y `negocios` restringido a:
    `auth.uid() = (SELECT user_id FROM negocios WHERE id = negocio_id)`.
* **Inserción de Pedidos:**
  * INSERT público permitido en `pedidos` (cualquier visitante puede generar un pedido para un negocio existente).
  * UPDATE de estado en `pedidos` restringido exclusivamente al propietario del negocio o domiciliario asignado.

## 4. Almacenamiento Multimedia (Supabase Storage)

* **Bucket:** `product-images` (Público).
* **Uso:** Almacena logos de comercio (`negocios.logo_url`) y fotografías de platillos/productos (`productos.imagen`).
* **Políticas:** `Public Access product-images` para SELECT y carga de imágenes.
* **Buenas Prácticas:**
  * Validar tamaño máximo de subida (idealmente <= 2 MB).
  * Convertir o comprimir a formato WebP o JPEG antes o durante la carga.
  * Organizar los archivos en carpetas dentro del bucket: `${negocio_id}/products/${filename}`.

## 5. Publicación en Tiempo Real (Realtime)

Las tablas `pedidos` y `productos` están agregadas a la publicación nativa `supabase_realtime`:
```sql
ALTER PUBLICATION supabase_realtime ADD TABLE pedidos;
ALTER PUBLICATION supabase_realtime ADD TABLE productos;
```
Esto permite que el panel de administración (`OrdersView.jsx`) reciba eventos instantáneos (`INSERT`, `UPDATE`) sin necesidad de recargar la página cuando un cliente realiza una compra.
